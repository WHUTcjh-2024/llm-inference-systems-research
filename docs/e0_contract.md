# E0：固定三轮状态机的 CPU 合同

上游参照：`fasa-org/dash-attention` commit `5e1c55124cd1645b5234a1af12866b7b5f8bfa2e`，文件 `dash_attn/decoding/stage2_block_selection.py`，锁定 SHA-256 `2b97c19728e71caf77d1772cd1f928174b606b46f4357c28c18fe096df6b80e5`。本地 oracle 使用 NumPy 双精度解释相同的控制流；它不执行 Triton，也不声称与 GPU 逐位一致。

## 输入和状态

- `z_i` 是 Stage 1 已存储的有效 chunk 分数，`x_i=z_i/2`。正常域要求至少一个 `z_i>-1e9`、全部分数有限、三个更新的分母和候选阈值有限。
- 最大值初始化沿用 Stage 1 的 `-1e9` 哨兵；`t_hi=max(-1e9,max(z))/2`，`t_lo=t_hi-1`，`t=(t_lo+t_hi)/2`。
- 每轮按固定源码计算 `f=Σ[x_i-t]_+²-1`、`f′=-2Σ[x_i-t]_+`、`f″=2Σ1{x_i>t}`，再计算 Halley 候选、更新括区间并用 `EPS=1e-5` 检查候选。
- 第三轮**更新后**的阈值用于概率、GQA 组均值、可选 `estimate_diag` 变换，以及 `nchunks` 位置恒为 1 的尾块 prior/bitmask。

## 候选认证命题

节点覆盖一组 chunk，且 `U_N≥max_{i∈N}x_i`。先用上界与已精算叶认证每头最大值。若某轮开始时参考路由与新路由的 `(t,t_lo,t_hi)` 相同，并且 `U_N≤t`，则该节点对本轮 `f/f′/f″` 的贡献均为零。对其余节点补算精确分数，可以归纳得到相同的三个实数状态。**这只允许当前轮暂缓**；下一轮阈值下降时必须重新检查。最后还要按 `t_3` 补算可能有正概率的节点，才能构造 prior 和 bitmask。

`scripts/e0_oracle.py` 以独立的全扫描路径和暂缓路径验证这个命题，并记录最大值认证成本、总精算叶数和重新激活次数。L2 球界只作为 CPU 合成例子的可计算上界；E0 会用已知精确分数检查每个界，但实际 GPU 算法不能借此检查。E0 的工作量数字不能作为 E2/E3 的性能估计。

## 独立数值样例

`tests/test_e0_oracle.py` 额外固定了用有理数手算的结果，不调用全扫描路径生成期望值。对单个 `x=1`，初值 `t₀=1/2`，首轮 `f=-3/4`、`f′=-1`、`f″=2`；三轮后的阈值依次为 `1/14`、`1/9842`、`1/3812798742494`。对两个相等的 `x=[1,1]`，首轮 `f=-1/2`、`f′=-2`、`f″=4`；三轮阈值依次为 `3/10`、`577/1970`、`4478554083/15290740090`。这些样例检查公式翻译，但不能替代实际 Triton 对照。

## 条件式 FP32 上界

`scripts/e0_fp32_bounds.py` 给出一套**可复算的 CPU 原型**。它从已存储的 FP32 `q,k` 和正的 FP32 `scale=s` 构造每个节点的坐标包络：对每个维度，`q_j≥0` 取节点内最大的 `k_ij`，否则取最小的 `k_ij`。于是所有叶子的实数点积都不超过 `C=Σ_j q_j·extreme_j`。另取 `S=Σ_j |q_j|·max_i|k_ij|`，则每片叶子的乘积绝对值之和不超过 `S`。

推导的**运算前提**是：`tl.dot` 每个叶子的路径至多包含 `D` 次乘法和 `D` 次加法；每次运算满足 `|fl(y)-y|≤u|y|+β`，其中 `u=2⁻²⁴`、`β=2⁻¹²⁶`。`β` 保守覆盖输出的次正规数被 flush to zero；输入中的非零次正规数直接拒绝。还要求乘以已知 FP32 `scale` 满足同一误差模型，最后乘 `0.5` 在未下溢时精确、下溢时误差不超过 `β`，且不存在溢出、NaN 或额外降精度。代码以精确有理数计算，令 `ρ=(1+u)^(2D)`，有

```text
E_dot = (ρ−1)S + 2D·β·ρ
M_dot = ρ(S + 2D·β)
E_z   = s·E_dot + u·s·M_dot + β
U_raw = (s·C + E_z)/2 + β
```

`M_dot` 还用于排除中间值及缩放的 FP32 溢出。`U_raw` 最后严格向上舍入到 FP32，才作为 `x=fl32(fl32(dot·s)/2)` 的候选上界。测试把此界与独立的逐次 FP32 乘加模拟结果比较，并检查不支持的输入会被拒绝。坐标包络预处理仍读取节点内所有 key；它**不是**已实现的低成本 GPU 算法，也不能用其 CPU 耗时评估收益。

关键前提尚未在目标 GPU 上核实：`input_precision="ieee"` 指定了 Triton 的精度模式，但[官方 `tl.dot` 文档](https://triton-lang.org/main/python-api/generated/triton.language.dot.html)没有承诺上述逐运算误差模型或具体归约 DAG。要将 `U_raw` 用作论文的 GPU 认证界，必须检查锁定版本在目标卡、输入 dtype 和编译配置下生成的运算，并用真实 Stage 1 `scores` 做全量覆盖测试。任何前提无法核实、边界非有限或覆盖失败时，A2 必须回退原路由；不能调一个经验 `δ` 后继续宣称严格认证。

## 不能从 E0 推出的结论

- 上面的 `E_z` 是条件式推导，不是对锁定 Triton kernel 的已验证误差界。`tl.dot(..., input_precision="ieee")` 的编译路径、实际 `scale`、分组约减及 FP32 舍入仍需 GPU 核实。上界覆盖实数点积不等于覆盖 GPU 实际分数。
- NumPy 的约减顺序与 Triton 的 tile/warp DAG 不同；E0 状态相等不保证 GPU prior 逐位相等。正常域 GPU 目标仍是 bitmask 零失配、prior 误差不超过预注册容差。
- 全遮罩、零完整 chunk、非有限分数或退化分母留给原实现回退；回退成本须在 E3 计入。
- 尚无真实 H20 trace、实际界紧度、route 时间或 TPOT。E1 完成后才能判定是否继续 A0/A1/A2。
